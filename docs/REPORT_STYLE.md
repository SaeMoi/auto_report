# REPORT_STYLE — 보고서 문체 규칙

- 버전: v0.1 (2026-11-16 초안)
- 적용: 양식 0·1·2 본문, 사람이 쓰는 노션 입력, AI 작성·다듬기 프롬프트, 검사 규칙 R-14·R-17·R-27
- 원본 관계: 사람과 프롬프트와 검사기가 이 파일 하나를 읽음. 본문 표는 사람이 읽고, 끝의 YAML 블록은 프로그램이 읽음. 두 곳을 고칠 때는 함께 고침
- 출처: 보고서 작성법 글(서술형 개조식, 간결 기준 5가지), 외부 검토 피드백(2026-11-15), 규격서 v0.3 5장

## 1. 기본 원칙

- 내용은 사람이 씀. AI는 문체·길이·용어만 다듬고, 사실·순서·수치·경로·ID는 바꾸지 않음
- 칸마다 적용하는 규칙이 다름. 4장 「칸별 적용표」를 먼저 확인함
- 이미 규칙을 지키는 문장은 고치지 않음

## 2. 문장 형태

| ID | 규칙 | 예 |
| --- | --- | --- |
| ST-01 | 서술형 개조식으로 씀. 조사·부사는 생략하지 않고 충분히 씀 | (X) 입력값 검증 미흡 → (O) 입력값을 검증하지 않아 스크립트가 실행됨 |
| ST-02 | 종결: 수행 결과·확인한 사실은 「~하였음·~되었음·~확인하였음」, 기준·규칙·계획·상태는 「~함·~임·~할 예정임」 | 결과: 관리자 API에 인증 없이 접근할 수 있음을 확인하였음 / 규칙: 개인정보는 마스킹하여 저장함 |
| ST-02a | 설명 칸 예외: 상세내용(위치·재현 과정·공격 설명·결과·대표 건과 다른 점), 악용 시나리오, 공격 내러티브, 미탐 분석, 사고 요약은 「~하였음」을 강제하지 않음. 「~함·~됨·~임」 현재형과 연결 어미(~하여, ~하고, ~하므로)를 씀. ST-04 길이 권장은 적용하지 않음 | 서버는 keyword 값을 인코딩하지 않고 결과 페이지에 넣으므로, 브라우저가 입력값을 script 태그로 해석함 |
| ST-03 | 「~습니다·~요·~한다·~다.」 종결은 어느 칸에서도 쓰지 않음 | (X) 스크립트가 실행된다. → (O) 스크립트가 실행됨 |
| ST-04 | 한 문장에는 한 가지 내용만 씀. 길어지면 나눔 | 30\~60자 안팎 권장 |

- 항목 끝에는 마침표를 찍지 않음. 한 항목 안에 문장이 둘 이상이면 문장 사이에만 마침표를 씀

## 3. 간결하게 쓰기

| ID | 규칙 | 예 |
| --- | --- | --- |
| ST-05 | 비슷한 내용은 묶어 항목으로 나눔 | 같은 원인의 건은 한 항목에 건 ID를 나열함 |
| ST-06 | 같은 단어·구절을 반복하지 않음 | (X) 취약점이 존재하는 취약한 페이지 |
| ST-07 | 의미가 겹치는 표현을 쓰지 않음 | (X) 사전에 미리, 다시 재확인, 기존에 있던 |
| ST-08 | 미사여구·수식어를 쓰지 않음. 정도를 나타내는 부사는 근거 수치가 있을 때만 씀 | (X) 매우 심각한 취약점 → (O) CVSS 8.8(High) 취약점 |
| ST-09 | 단어를 지나치게 압축하지 않음. 주어와 시제가 드러나게 씀 | (X) 권한 검증 미흡으로 접근 가능 → (O) 서버가 권한을 확인하지 않아 회원이 관리자 기능을 호출할 수 있음 |
| ST-10 | 한 항목에 너무 많은 내용을 담지 않음. 보고 목적과 관계없는 내용은 뺌 | 도구 사용 소감, 진행 중 겪은 어려움은 쓰지 않음 |

## 4. 칸별 적용표

| 문서 · 위치 | 칸 | 종결 규칙 | 길이 | 작성 주체 |
| --- | --- | --- | --- | --- |
| 양식 0 전체 | 규칙·계획 | ST-02 (~함·~임) | ST-04 | 사람 |
| 결과 4-1 | 총평 | ST-02 (~하였음) | 5문장 이내 | AI 작성 |
| 결과 4-4 | 잘 된 보안 사항 | ST-02 | 항목당 1문장 | 사람 + AI 다듬기 |
| 결과 5장 | 개요(overview) | ST-02 | 1\~2문장 | 사람 + AI 다듬기 |
| 결과 5장 | 악용 시나리오(exploit\_scenario) | ST-02a | 원문 ±30% | 사람 + AI 다듬기 |
| 결과 5장 | 상세내용 위치·재현 과정·결과 | ST-02a | 제한 없음 | 사람 |
| 결과 5장 | 공격 설명(poc.explanation) | ST-02a | 원문 ±30% | 사람 + AI 다듬기 |
| 결과 5장 | 대표 건과 다른 점(diff) | ST-02a | 1\~3문장 | 사람 + AI 다듬기 |
| 결과 6-1 | 시나리오 결과 | ST-02 | 1\~2문장 | 사람 |
| 결과 6-2 | 수행 내용(narrative) | ST-02a | 2\~5문장 | AI 작성 |
| 결과 7-2 | 조치방안(remediation.steps) | ST-02 (~함) | 3\~6개 항목 | 사람 + AI 다듬기 |
| 결과 7-2 | 확인 방법(remediation.verify) | ST-02 (~함) | 1\~3문장 | AI 작성 |
| 공통 | 그림 설명(caption) | 명사형 | 1문장, 40자 이내 | 사람, 비면 AI 작성 |
| 블루 1-1·1-4 | 위험 요약·사업 영향 | ST-02 | 각 1\~2문장 | AI 작성 |
| 블루 5-2 | 미탐 케이스 분석 | ST-02a | 3문항, 문항당 1\~2문장 | AI 작성 |
| 블루 9장 | 사고 요약(incident.summary) | ST-02a | 3\~5문장 | AI 작성 |
| 블루 11-1·11-2 | 교훈·잘 된 방어 | ST-02 | 항목당 1문장 + 근거 D-ID | AI 작성 |

- 표에 없는 칸은 ST-02를 따름
- 코드 블록, HTTP 요청·응답, 표의 값 칸은 문체 규칙을 적용하지 않음

## 5. 표기

| ID | 규칙 | 예 |
| --- | --- | --- |
| ST-11 | OWASP 범주는 코드와 영문 원문을 함께 씀 | A05 Injection |
| ST-12 | CWE는 「CWE-번호」로 씀. 이름이 필요하면 영문 원문을 뒤에 둠 | CWE-79 Improper Neutralization of Input During Web Page Generation |
| ST-13 | 취약점명은 분류 코드 가이드 2장의 권장 이름을 그대로 씀 | Reflected XSS, IDOR |
| ST-14 | 위험도 등급은 영문으로 쓰고, 점수를 함께 쓸 때는 「High(CVSS 8.1)」 형식으로 씀 | Critical, High, Medium, Low, Info |
| ST-15 | ID는 정해진 형식을 그대로 씀. 문장 안에서는 괄호로 붙임 | 관리자 API에 인증 없이 접근할 수 있음을 확인하였음(V-05-1) |
| ST-16 | 시각은 「YYYY-MM-DD HH:MM:SS KST」, 날짜는 「YYYY-MM-DD」로 씀 | 2026-11-20 14:03:22 KST |
| ST-17 | 인용·강조는 「 」를 씀. 작은따옴표·큰따옴표는 코드와 원문 인용에만 씀 | 「블루팀 검증 전」 |
| ST-18 | 민감정보는 마스킹한 값만 씀. 마스킹 형식은 앞 2자 + \*\*\* | ad\*\*\*, 010-\*\*\*\*-1234 |

## 6. AI 작성·다듬기 규칙

| ID | 규칙 |
| --- | --- |
| ST-19 | 다듬기는 2\~5장 규칙에 맞추는 것만 함. 원문의 사실·순서·수치·경로·URL·ID·코드는 바꾸거나 빼지 않음(R-27) |
| ST-20 | 다른 칸의 사실을 가져와 붙이지 않음. 원문이 비어 있으면 채우지 않고 「사람이 채울 칸」으로 돌려보냄 |
| ST-21 | 작성(write) 작업은 입력 데이터에 있는 사실만 씀. 근거가 부족하면 「\[확인 필요\]」로 표기함 |
| ST-22 | 작성 작업의 문장에는 근거 ID(V-NN-N, SN-STEPN, D-NN, E-NNN)를 1개 이상 괄호로 붙임. 다듬기 작업은 원문에 있던 ID만 유지함 |
| ST-23 | 숫자는 집계값만 씀. 비율·평균을 새로 계산하지 않음 |
| ST-24 | 확인한 것과 시도하지 않은 것을 구분함. 시도하지 않은 것은 「~할 가능성이 있음」으로만 씀 |

## 7. 용어집

| 쓰는 말 | 쓰지 않는 말 | 비고 |
| --- | --- | --- |
| 취약점 | 취약 항목, 이슈 | V-xx 단위 |
| 건 | 케이스, 인스턴스 | V-xx-n 단위 |
| 대표 건 | 주요 건, 메인 건 | V-xx-1 |
| 위험도 | 심각도, 위험 등급 | |
| 조치방안 | 해결 방안, 대응 방안 | 결과 보고서 7장 |
| 악용 시나리오 | 공격 시나리오(5장에서) | 6장 시나리오 모의해킹과 구분 |
| 재진단 | 재점검, 리테스트 | 결과 8장 |
| 와주 | Wazuh(본문) | 그림·명령어·설정 값은 Wazuh |
| 경보 | 알람, 얼럿 | |
| 미탐 | 탐지 실패, 미탐지 | |
| 출발지 IP | 소스 IP, 공격 IP | |
| 마스킹 | 가림 처리, 블라인드 | |

## 8. 기계 판독 블록

프로그램(R-14·R-17·R-27, 프롬프트 생성기)은 아래 블록만 읽음.

```yaml
version: 0.1
banned_endings:          # ST-03, 모든 칸
  - "습니다"
  - "합니다"
  - "해요"
  - "어요"
  - "한다."
  - "된다."
  - "이다."
result_endings:          # ST-02 결과 칸 권장
  - "하였음"
  - "되었음"
  - "확인하였음"
rule_endings:            # ST-02 규칙·계획 칸 권장
  - "함"
  - "임"
  - "됨"
  - "할 예정임"
loose_fields:            # ST-02a 적용 칸
  - finding.exploit_scenario
  - finding_instance.poc.location
  - finding_instance.poc.steps
  - finding_instance.poc.explanation
  - finding_instance.poc.response
  - finding_instance.diff
  - scenario_step.narrative
  - test_case.miss_analysis
  - incident.summary
banned_adverbs:          # ST-08, 근거 수치 없으면 경고
  - "매우"
  - "극히"
  - "완전히"
  - "심각하게"
  - "모든"
  - "절대"
redundant_phrases:       # ST-07
  - "사전에 미리"
  - "다시 재확인"
  - "기존에 있던"
  - "미리 예방"
  - "함께 동반"
sentence_length:         # ST-04, ST-02a 칸은 제외
  recommend_min: 30
  recommend_max: 60
field_length:            # 규격서 5-2와 같은 값, R-17
  finding.overview: {sentences: [1, 2]}
  finding.exploit_scenario: {ratio_to_source: [0.7, 1.3]}
  finding_instance.poc.explanation: {ratio_to_source: [0.7, 1.3]}
  finding_instance.diff: {sentences: [1, 3]}
  finding.remediation.steps: {items: [3, 6]}
  finding.remediation.verify: {sentences: [1, 3]}
  scenario_step.narrative: {sentences: [2, 5]}
  summary.overall: {sentences: [1, 5]}
  pentest.summary: {sentences: [3, 6]}
  scenario_step.flow: {ratio_to_source: [0.7, 1.3]}
  scenario_step.rationale: {ratio_to_source: [0.7, 1.3]}
  evidence.caption: {sentences: [1, 1], max_chars: 40}
  blue.risk_summary: {sentences: [1, 2]}
  blue.business_impact: {sentences: [1, 2]}
  incident.summary: {sentences: [3, 5]}
preserve_in_polish:      # ST-19, R-27이 원문과 비교하는 대상
  - number
  - id                   # A-xx, V-xx-n, Sn-STEPm, D-xx, F-xx, P-xx, E-xxx, CWE-n, CVE-yyyy-n, Axx
  - path
  - url
  - code                 # 백틱·코드 블록 안 내용
glossary:                # 7장, 왼쪽 → 오른쪽으로 바꿔 쓰라고 경고
  "취약 항목": "취약점"
  "이슈": "취약점"
  "케이스": "건"
  "인스턴스": "건"
  "심각도": "위험도"
  "위험 등급": "위험도"
  "리테스트": "재진단"
  "재점검": "재진단"
  "알람": "경보"
  "얼럿": "경보"
  "탐지 실패": "미탐"
  "소스 IP": "출발지 IP"
```
